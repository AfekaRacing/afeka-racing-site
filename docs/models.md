# מודלים תלת-ממדיים: מ-SolidWorks לאתר

## הדרך האוטומטית (מה שבפועל בנינו)

על מחשב שמותקן בו SolidWorks אפשר להמיר את כל הרכב בשתי פקודות, בלי Blender:

1. שמים את קבצי ה-SolidWorks בתיקייה `Solid Assembly` בתוך תיקיית האתר. התיקייה לא עולה ל-Git.
2. בפעם הראשונה בלבד, בונים את כלי הייצוא:

```bash
scripts\cad\build.cmd
```

3. מייצאים מ-SolidWorks. הכלי מתחבר ל-SolidWorks הפתוח, או פותח אותו בעצמו:

```bash
scripts\cad\swmesh.exe export "Solid Assembly\Full Assembly.SLDASM" models-source\stl
```

4. ממירים לקבצים של האתר:

```bash
npm run models
```

**מה כל שלב עושה:**
- **`swmesh`:** קורא את המכלול דרך הממשק הרשמי של SolidWorks. לכל רכיב ראשי הוא שומר רשת משולשים במיקום המדויק שלו ברכב. חלקים מוסתרים, מדוכאים (suppressed) וחלקי דמה ("dummy") לא נכללים.
- **`npm run models`:** עושה את מה שעושים ידנית ב-Blender. הוא מאחד כל רכיב לקובץ אחד, מסובב לצירים של האתר, מקטין את מספר המשולשים, דוחס, ושומר ב-`public/models/<id>.glb`.

איזה רכיב ראשי במכלול שייך לאיזה רכיב באתר, וכמה משולשים מותר לכל אחד: הרשימה `PARTS` בתחילת `scripts/build-models.mjs`. כדי לראות את מבנה המכלול:

```bash
scripts\cad\swmesh.exe list "Solid Assembly\Full Assembly.SLDASM" models-source\tree.txt
```

**חסרים כרגע במכלול:** פאנלים סולאריים ו-PDU/EMU. ברגע שהם יתווספו למכלול, מוסיפים שורה ל-`PARTS` וממלאים את `model` ב-`src/data/parts.ts`.

ההוראות הידניות למטה נשארו לשימוש בלי SolidWorks.

## למה בכלל צריך המרה? (ההסבר בקצרה)

- **SolidWorks שומר גאומטריה מתמטית מדויקת:** משטחים וקשתות מוגדרים בנוסחאות. דפדפן לא יודע להציג את זה.
- **דפדפן מציג רק רשת של משולשים (mesh).** כל משטח מעוגל הופך להרבה משולשים קטנים. ככל שיש יותר משולשים, הרכב נראה חלק יותר, אבל הקובץ כבד יותר והטלפון איטי יותר.
- **לכן ההמרה היא בשלושה שלבים:**
  1. **ייצוא (SolidWorks):** הופכים את המודל לרשת משולשים (STL או STEP).
  2. **הקטנה (Blender):** מורידים את מספר המשולשים בלי שהצורה תשתנה בעין. זה נקרא Decimate.
  3. **אריזה לאתר (Blender):** שומרים כ-GLB, הפורמט שהאתר יודע לטעון, עם דחיסה.
- **למה קובץ נפרד לכל רכיב:** כדי שהאתר יוכל להזיז כל רכיב בנפרד בפירוק ולהדגיש אותו בלחיצה.

## Blender בשתי דקות

Blender היא תוכנת תלת-ממד חינמית. בשבילנו צריך להכיר רק כמה דברים:

| מה | איך |
|---|---|
| סיבוב המבט | גרירה עם הגלגלת (כפתור אמצעי) |
| הזזת המבט | Shift + גרירה עם הגלגלת |
| זום | גלגלת |
| בחירת אובייקט / הכול | קליק / A |
| מחיקה | X |
| שינוי גודל | S, מקלידים מספר, Enter |
| התמקדות באובייקט שנבחר | מקש הנקודה במקלדת המספרים (Numpad .) |
| הפאנל של האובייקט | מצד ימין: לשונית המפתח הכחול (Modifiers) |

המטרה: קובץ GLB קטן לכל רכיב, שכולם יושבים באותה מערכת צירים, כדי שהאתר יוכל להרכיב ולפרק אותם.

הדרך: **SolidWorks → STEP → Blender → GLB**.

## מה צריך

- SolidWorks עם המכלול המלא של אורנע 2.
- [Blender](https://www.blender.org/download/) בגרסה 4.2 ומעלה. חינמי.
- **שימו לב:** Blender לא פותח STEP בלי תוסף (למשל STEPper, שהוא בתשלום). אם אין לכם תוסף כזה, הדרך החינמית היא לייצא מ-SolidWorks ל-**STL** (חלופה ב׳ בשלב 1). התוצאה באתר זהה.
- בגרסאות SolidWorks חדשות יש גם **Save As → Extended Reality (\*.glb)**. אם הוא קיים אצלכם, אפשר לייצא GLB ישירות ולעבור משם לשלב 2 לצורך הקטנת הפוליגונים.

## 1. ייצוא מ-SolidWorks

**חשוב: מייצאים כל רכיב מתוך המכלול המלא, ולא מתוך קובץ החלק.** ככה כל קובץ שומר על המיקום שלו ברכב, והרכיבים מתיישבים במקום הנכון באתר בלי כיוונונים.

לכל אחד מ-11 הרכיבים (שלדה, קשת התהפכות, מתלה קדמי, מתלה אחורי, מסרק הגה, מערכת בלימה, ג׳אנטים, סוללה ומארז, PDU ו-EMU, פאנלים סולאריים, מעטפת וחופה):

1. פותחים את המכלול הראשי של אורנע 2.
2. מסתירים (Hide) את כל מה שלא שייך לרכיב הנוכחי.
3. **File → Save As → STEP AP214 (\*.step)**.
4. ב-Options מסמנים **Export: Visible components only** (או "Export selected bodies").
5. שומרים בשם באנגלית, לפי הטבלה למטה (למשל `chassis.step`).

**חלופה ב׳ (בלי STEP):** **Save As → STL**. ב-Options בוחרים Resolution: **Coarse** או Custom עם Deviation של 0.5 מ״מ, ומסמנים **Do not translate STL output data to positive space**. האפשרות האחרונה חשובה כדי לשמור על המיקום ברכב.

| רכיב | שם קובץ |
|---|---|
| שלדה | `chassis` |
| קשת התהפכות | `rollbar` |
| מתלה קדמי | `front-suspension` |
| מתלה אחורי | `rear-suspension` |
| מסרק הגה | `steering` |
| מערכת בלימה | `brakes` |
| ג׳אנטים וצמיגים | `wheels` |
| סוללה ומארז | `battery` |
| PDU ו-EMU | `pdu-emu` |
| פאנלים סולאריים | `solar` |
| מעטפת וחופה | `body` |

השמות חייבים להתאים ל-`id` שבקובץ `src/data/parts.ts`.

## 2. ייבוא ל-Blender וניקוי

1. פותחים Blender חדש ומוחקים את הקובייה, המצלמה והאור (A, ואז X).
2. **File → Import** ובוחרים את קובץ ה-STEP (או ה-STL).
3. **יחידות:** SolidWorks עובד במילימטרים והאתר במטרים. אם הרכב נראה ענק:
   - בוחרים הכול (A), לוחצים S, מקלידים `0.001` ו-Enter.
   - **Object → Apply → Scale**.
4. **צירים:** באתר x הוא קדימה, y הוא למעלה ו-z הוא לצד. Blender מסובב אוטומטית בייצוא ל-glTF (Z-up → Y-up), אז בדרך כלל לא צריך לגעת. אם הרכב יוצא מסובב באתר, מתקנים פעם אחת את `modelTransform` ב-`parts.ts` ולא את הקבצים.
5. **איחוד:** בוחרים את כל החלקים של הרכיב, **Ctrl+J** (Join). מתקבל אובייקט אחד. נותנים לו את שם הרכיב (F2).
6. **מיקום:** **לא** מזיזים את האובייקט ולא עושים Set Origin to Geometry. המיקום המקורי מהמכלול הוא מה שמרכיב את הרכב באתר.

## 3. הקטנת מספר הפוליגונים

קבצי CAD הם צפופים מאוד, והאתר צריך להיות קל, במיוחד בנייד.

1. בוחרים את האובייקט, ובלשונית המפתח הכחול (Modifiers): **Add Modifier → Generate → Decimate**.
2. **Collapse** עם Ratio:
   - שלדה, מתלים וחלקים צינוריים: 0.2 עד 0.4.
   - מעטפת: 0.1 עד 0.2.
   - חלקים קטנים: 0.3 עד 0.5.
3. מסתכלים על **Face Count** (מופעל מ-Viewport Overlays → Statistics). יעד: **עד 30,000 משולשים לרכיב** ועד כ-200,000 לכל הרכב.
4. כשזה נראה טוב: **Apply** על המודיפייר (Ctrl+A מעל המודיפייר).
5. אם יש משטחים שנראים "מנוקדים": **Object → Shade Auto Smooth**.

## 4. צבע וחומר (לא חובה)

אם רוצים צבע משלכם: בלשונית Material יוצרים Principled BSDF ובוחרים Base Color. אם לא, הקובץ יוצג בצבעים שיצאו מ-SolidWorks.

## 5. ייצוא ל-GLB

1. בוחרים רק את האובייקט של הרכיב.
2. **File → Export → glTF 2.0 (.glb/.gltf)**.
3. בחלון הייצוא:
   - **Format:** glTF Binary (.glb).
   - **Include → Limit to: Selected Objects** ✔.
   - **Transform → +Y Up** ✔.
   - **Mesh → Apply Modifiers** ✔.
   - **Compression** ✔ (Draco). מקטין את הקובץ פי 5–10.
4. שומרים בשם מהטבלה, למשל `chassis.glb`.

יעד גודל: עד כ-1–2 MB לקובץ.

## 6. חיבור לאתר

1. מעתיקים את הקבצים לתיקייה `public/models/` בפרויקט.
2. פותחים את `src/data/parts.ts`, ובכל רכיב ממלאים את השדה `model`:

```ts
model: 'models/chassis.glb',
```

3. מריצים `npm run dev` ובודקים. רכיב עם `model` ריק ממשיך להציג את המודל הזמני, כך שאפשר להחליף רכיב אחד בכל פעם.

## בעיות נפוצות

| מה רואים | מה עושים |
|---|---|
| הרכיב ענק או זעיר | לא בוצע Scale של 0.001 (שלב 2.3), או ש-`modelTransform.scale` לא ב-1 |
| הרכיב שוכב על הצד | משנים את `modelTransform.rotation` ב-`parts.ts`, למשל `[-Math.PI / 2, 0, 0]` |
| הרכיבים לא מתיישבים יחד | כל רכיב חייב להיות מיוצא מתוך המכלול המלא, בלי להזיז אותו ב-Blender |
| הקובץ כבד והאתר איטי | Ratio נמוך יותר ב-Decimate, ולוודא ש-Compression מסומן |
| הרכיב לא נטען בכלל | לבדוק שהנתיב ב-`model` מתחיל ב-`models/` ושהקובץ באמת ב-`public/models/` |

## פירוק עדין יותר

הכיוון שאליו כל רכיב זז בפירוק נקבע בשדה `explode` ב-`parts.ts` (במטרים: `[קדימה, למעלה, לצד]`). אפשר לשחק בערכים עד שהפירוק נראה טוב עם המודלים האמיתיים.
